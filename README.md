# ChoMU — AI 3D Model Generator

ChoMU generates real 3D models from text prompts or images using **NVIDIA NIM
— Microsoft TRELLIS**, viewable in an in-app 3D viewer and exportable to
GLB / glTF / OBJ / STL / PLY / USDZ. Ships as a web app and as a native
Android app via Capacitor.

## Stack

- React 19 + TypeScript + Vite + Tailwind v4
- `three.js` / `@react-three/fiber` / `@react-three/drei` for the model viewer and exporters
- Capacitor (Android) for the native app shell
- `idb-keyval` (IndexedDB) for local generation history, `@capacitor/preferences` for settings
- Zustand for the generation queue

## NVIDIA API key

ChoMU calls `https://ai.api.nvidia.com/v1/genai/microsoft/trellis` directly
with a user-supplied API key entered in **Settings** inside the app. The key:

- is **never** hardcoded or committed to this repo,
- is stored only in on-device storage (Capacitor Preferences),
- is sent only as the `Authorization` header on requests straight to NVIDIA's API.

Get a free key at [build.nvidia.com](https://build.nvidia.com/microsoft/trellis).

### Known NVIDIA-side limitation (Image-to-3D)

As of testing, NVIDIA's hosted TRELLIS endpoint rejects custom image uploads
with `422 {"detail": "Expected: example_id, got: asset_id"}` — it currently
only accepts its own preset gallery images for image-to-3D, even though the
NVCF asset-upload flow completes successfully. **Text-to-3D works correctly
end-to-end.** ChoMU implements the full, correct image-upload flow (NVCF
asset create → presigned S3 upload → asset-reference generation call) so
image-to-3D will start working the moment NVIDIA lifts this restriction —
no app update required. The app surfaces this exact error rather than
faking a result.

NVIDIA's hosted function also scales its GPU workers to zero when idle; the
first request after idle time can take up to ~90s (cold start) and may
return a bare `500`. ChoMU retries once automatically and shows a "waking up
NVIDIA GPU worker" status while it does.

## Development

```bash
npm install
npm run dev      # browser dev server on :5173, proxies NVIDIA calls to dodge browser CORS
npm run build    # type-check + production build
```

The dev server proxies `/nvidia-genai` and `/nvidia-nvcf` to NVIDIA's API
purely so the app can be exercised in a desktop browser. On the real Android
build, requests go straight from native code via Capacitor's HTTP bridge
(`CapacitorHttp`), which isn't subject to browser CORS at all — the proxy
is unused there.

## Building the Android APK

```bash
npm run build
npx cap sync android
cd android
./gradlew assembleDebug
# APK at android/app/build/outputs/apk/debug/app-debug.apk
```

See `android/README.md` (generated by Capacitor) for signing a release build.

## Features

- **Text-to-3D** and **Image-to-3D** generation via real NVIDIA NIM calls (no mocked responses)
- **Generation queue** — batch multiple text prompts (one per line) and let them process sequentially with live status
- **3D viewer** with studio/sunset/city lighting presets, orbit + auto-rotate, correct PBR tone mapping (fixes the "black model" issue that comes from missing environment lighting)
- **Exporter** — GLB, glTF, OBJ, STL, PLY, USDZ, with a real (non-AI, canvas-based) texture resolution option (Original/1K/2K/4K/8K) for texture-carrying formats
- **Generation history** stored locally (IndexedDB), with thumbnails, re-viewing, re-exporting, deleting
- **Settings** — API key entry + a real "Test API key" button (validates against NVIDIA without paying for a full generation), light/dark/system theme
